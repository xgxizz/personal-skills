# Codex 独立执行与 OpenCode 协作：三轮本机评测

日期：2026-10-18（Asia/Shanghai）

## 结论

在这批小规模、单次运行的任务中，将已明确委派的旁支交给 OpenCode DeepSeek、直接使用返回结果，显著降低了执行阶段耗时。额外启动 Codex 独立审查会增加耗时，且本次没有降低 Codex token 总量。

这支持将 OpenCode 用作旁支执行工具的尝试，不支持把它自动应用到所有任务。最终采用的 Skill 保留“明确指定才调用、只用已配置免费模型、直接采纳结果”的规则。

## 三轮汇总

| 轮次 | 流程 | Codex 耗时 | 协作耗时 | 耗时变化 | Codex 最终通过 | 协作最终通过 | DeepSeek 原始通过 |
|---|---|---:|---:|---:|---:|---:|---:|
| 1：自定义短题 10 道 | DeepSeek 执行 + 额外 Codex CLI 审查 | 208.408 秒 | 374.626 秒 | +79.76% | 10/10 | 10/10 | 9/10 |
| 2：同样短题重新运行 | DeepSeek 原样直接交付 | 169.421 秒 | 63.752 秒 | −62.37% | 10/10 | 10/10 | 10/10 |
| 3：公开 HumanEval 随机 10 题 | DeepSeek 原样直接交付 | 181.077 秒 | 63.159 秒 | −65.12% | 10/10 | 10/10 | 10/10 |

每轮每组均只运行一次，不按得分重试。合计 60 组交付；前两轮题目重复，因此是 20 个不同题目，不能当作 30 个独立题目。第 1 轮协作组多了一次 Codex 审查请求，而免复核组没有这次请求。

第 1 轮 DeepSeek 将中位数回答为 3，正确值为 5，Codex 审查纠正了该题。第 2 轮相同题目 DeepSeek 答对，说明小样本单次运行会波动，不能据此推断稳定准确率差异。

口径：Codex token 为 CLI 报告的 input_tokens + output_tokens，缓存输入已包含在 input_tokens，不能再加一次。DeepSeek 参考合计为 OpenCode v2 返回的 input + output + reasoning + cache.read + cache.write，细项保存在各轮 summary.json。跨模型 tokenizer 和字段口径不同，合计仅供参考，不能直接当成等价费用。

“无额外执行/审查请求”不代表 Codex 总消耗为零：当前主聊天的任务规划、调度、接收及汇报 token 无法单独获取，记为 unavailable，没有纳入表中。两轮直接交付的 DeepSeek 会话均报告费用为 0；这不是跨服务总账单。

第 1 轮任务 9 的协作耗时为 139.781 秒，包含明显长等待；没有删除慢样本。两组总时间均包含 CLI 冷启动和网络等待。不同轮次还受到缓存、网络和提示差异影响，不可将跨轮全部差异归因于去掉复核。

## 任务与抽样

前两轮的 10 类任务为筛选去重求和、中位数与众数、区间合并、最短路径、日期计算、词频、SQL 连接、Python 引用语义、依赖排序和分组汇总。准确率为最终 JSON 与预定义结果精确匹配。

第 3 轮来自 [OpenAI HumanEval](https://github.com/openai/human-eval)，按保存的随机种子从全量 164 题无放回抽 10 题，不做难度筛选或重抽。源数据来自官方公开文件：

两组使用同一题面与约束，只生成一次完整 Python 模块，不使用工具、不联网、不运行测试。模型没有收到参考实现和官方测试。全部 20 份代码交付完成后，才由离线脚本执行官方 check 函数；测试结果不回传模型，不触发修复。评分前参考实现全部通过同一评分器，用于确认评分环境。

官方测试通过题数不等于穷尽正确性。仅移除输出最外层代码围栏以运行评分，不补写或修正生成代码。评分在独立 Python 子进程中执行并设超时，是本机适配评分器，不是官方完整沙箱或排行榜运行。

## 主要限制

1. 样本小，每题每组一次；没有置信区间、重复测量或完整基准得分。
2. 随机题包含简单题；没有测试真实项目、海量日志、长报告或多轮工具执行。
3. HumanEval 长期公开，可能存在训练数据污染；本轮结果不能证明陌生任务泛化能力。
4. Codex 使用本机 CLI 默认模型，具体型号未独立确认，也未确认与桌面当前聊天型号相同。OpenCode 固定 `opencode/deepseek-v4.1-flash-free`。
5. 测的是固定脚本路由和 CLI 执行，不是模型自主调度决策；主聊天调度 token 未计量。
6. 第 1 轮失败的连通性及执行策略预试未计入正式统计。报告不是整个聊天所有调用的总用量账单。
7. 两组没有锁定完全相同的系统上下文，也未统一不同供应商的采样参数，结果不能解释为纯模型能力排名。

## Skill 的最终设计

- 默认 Codex 自己工作；明确指定才调用 OpenCode。
- 整项交接有界旁支流程，必要自检由 OpenCode 一次完成。
- Codex 直接采用结果；只检查调用状态和交付是否完整，用户另行要求才复审。
- 简短结果回传，完整报告落盘；明确任务、输出目录和会话 ID。
- 暂时失败有限重试；测试报告中的失败项是有效发现，不自动修代码。
- 长任务保存可恢复进度；不额外引入多层规划、共识或审核代理。

社区项目提供了上下文交接、文件产物、续接与状态管理的设计参考；“默认不复核”是本用户的明确偏好，并非社区统一标准。来源及取舍见 [交接参考](../skills/opencode-on-demand/references/handoff.md)。
